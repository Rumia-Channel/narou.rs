# v0.4.7 release preparation

Base: develop d87c5574d4d91a2d0dbe3ec193fd3c30052f59eb.
Package versions: narou_rs / narou_worker 0.4.7.
Cargo.lock was regenerated by cargo check; only these two package versions changed.

Included fixes (all on develop, each with its own commit):
- #35 freeze state in SQLite mode: writes go through `Inventory::update_yaml`, legacy
  `freeze.yaml` import is a union, `frozen_novels` is projected, and
  `narou db repair-freeze [--dry-run]` restores ids lost by older builds.
- Worker console streaming: `PushHubSink` sends each line as it is emitted
  (`application::messages::flush::FlushQueue` owns order/no-loss/throttle).
- `webui.debug-mode` detail logging (`application::debug`) on both runtimes plus a
  devtools mirror in `main.js`; Worker EPUB illustrations are rewritten from the
  source URL to the stored `挿絵/<file>` via `.illustration_cache.yaml`.
- Deploy fix: the post-deploy S3 probe sends a browser-like User-Agent (Cloudflare's
  bot rules answered urllib's default UA with 403) and the smoke now runs the same
  `?probe=s3` check.

License notices (`Third-Party-License*.md`) and `about-probe/Cargo.lock` carry the
package version, so they were updated in the same commit as the manifests.

Validation before the release commit:
- cargo check --workspace --all-targets
- cargo check -p narou_worker --target wasm32-unknown-unknown
- cargo test --workspace --all-targets --features lite
- cargo clippy --workspace --all-targets --all-features -- -D warnings, cargo doc -D warnings

Integration into main, the tag and publishing are separate steps.
