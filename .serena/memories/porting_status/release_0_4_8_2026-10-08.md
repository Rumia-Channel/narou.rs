## Included fixes (all on develop, each with its own commit)

- **新規ダウンロードの ID 二重採番** (`5136141`): `Downloader` は開始時に `allocate_id()` で
  ID を予約し、その ID を DL開始行に出す。以前はコミット時にもう一度採番していたため、
  `ID:1　タイトル のDL開始` → `タイトル のDL完了 (ID:2, …)` と食い違い、使われない ID が
  1 つ消費されて一覧の ID が飛んでいた (既存データは偶数 ID ばかりになる)。
  予約した ID をそのままレコードに使うようにした (native CLI / native Web UI / Worker 共通の
  core `src/downloader/mod.rs`)。回帰は `tests/download_new_novel_id.rs` (2 作品が連番になること)。
- **Web UI の進捗バーが残る** (`8bf0351`, `31791dc`): バーは job id を scope に持つため、
  clear を取りこぼすと「進捗 0/0 0.0%」が積み重なっていた。同じコンソール・同じ topic の
  job バーを 1 本にまとめ、`queue_complete` / `queue_failed` / `queue_partial` /
  `queue_cancelled` の job id で消去し、キューが空 (`running_count == 0 && pending == 0`) に
  なった時点で job スコープのバーを全部消す。scope を持たないバー (自己アップデート) は対象外。
  回帰は `tests/progress_bars.test.mjs`、CI は `platform.yml` の Web UI 回帰ステップに追加。
- **SORAHOST と Workers の同一ホスト名** (`7eb5618`, `4ff29d3`, `8366062`): 動いている側が
  ホスト名を持つ。Workers が後から配備される場合は `NAROU_DOMAIN_MODE=route` で
  custom domain ではなく route に載せ替え、SORAHOST のコネクタが作った DNS に触れない。
- **Access の 403 を S3 プローブのスキップとして扱う** (`82c6d1c`): 成功とは区別して報告する。

## 注意 (次回以降)

- `tests/worker_dispatch.test.mjs` は Windows の作業ツリー (`core.autocrlf=true`) で CRLF に
  なるため、そのままでは `node --test` が失敗する (blob は LF なので Linux CI では通る)。
  手元で回すときは `git -c core.autocrlf=false` で checkout するか、CRLF を許容する正規表現に
  直すのが望ましい。
- `git push` はサンドボックス下で `schannel: AcquireCredentialsHandle failed` になる。
  資格情報を使える権限で実行する必要がある。
