## Included fixes (all on develop, each with its own commit)

- **CLI のログに小説ごとの行が出ない (issue #36)** (`db1c771`): `narou update` / `narou download`
  は小説ごとの状況をコンソールに出していたが、ログには最後の `n 件のエラーが発生しました`
  しか残らず、どの小説が失敗したのか追えなかった。原因は 2 つ:
  (1) `src/logger.rs` が bin (`main.rs` の `mod logger`) と lib (`narou_rs::logger`) の両方に
  コンパイルされて `LoggerState` が 2 つ存在し、`logger::init()` が bin 側しか初期化していなかった。
  lib 側の logger を通る行 (`MessageSink` / `progress::console_sink` 経由) は未初期化の
  `disabled()` のままだった。bin は lib のロガーを共有するようにした (`find_narou_root` と
  `latest_log_path_in` を pub 化、`commands/web.rs` の二重 init を 1 回に)。
  (2) Downloader のレポート行 (DL 開始・章/節の見出し・話ごとの進捗・
  「小説が削除されているか非公開な可能性があります」) は、ドメイン別並列化の際に
  logger を迂回する `direct_console_sink` (= `safe_println`) へ移されていた。`console_sink()`
  に統一し、`DirectConsoleSink` は削除。`ConsoleSink` は `STDOUT_LOCK` を取るので並列時の
  行混線防止は維持される。回帰は `tests/cli_logging.rs` (実バイナリを起動し、sink 経由行と
  bin 側行が同じログに入ることを固定。修正を戻すと fail することを確認済み) と
  `src/downloader/mod.rs` の `downloader_report_lines_reach_the_log_file`。
- **挿絵が EPUB に入らない / 取り直されない** (`10aff97`, `4976133`, `09dfa68`, `7ebb60c`,
  `aa28ceb`, `6684956`): サイト定義に `illust_grep_pattern` が無いサイト (なろう / R18なろう /
  カクヨム / Arcadia) でも narou.rb `HTML#initialize` の既定 `<img>` パターンでダウンロード時に
  挿絵を取得する (protocol-relative の解決、mitemin の `viewimagebig` → `viewimage`、URL でない
  注記は対象外、空の `.illustration_cache.yaml` は作らない)。索引が知っているのに実体が無い
  挿絵は `<prefix>/挿絵` を 1 小説 1 回だけ一覧して取り直す。EPUB 側は、ストアの一覧が空を
  返しても参照された画像を `platform::illustration_key` で 1 件ずつ stat してから組み立てる
  (一覧は速い経路として残す)。一覧が空のときは欠落の在り処を WARN で報告する。
- **Worker のコンソール分離** (`2ddfe77`, `3476355`): convert ジョブの出力を
  `Stream::target_console_with` の規則で `stdout2` へ回し、`PushHubSink` にコンソール
  上書きを渡す。`concurrency` が worker では無効扱いだったため設定画面から入れず 2 ペイン目が
  空だった問題を解消し、既定で分離オン (`concurrency=false` を明示保存したときだけ単一)。
- **挿絵のデバッグ行** (`6684956`): 既定パターンの案内が話数だけ繰り返し出ていたのを索引
  読み込み時に 1 回へ、保存行のファイル名に拡張子が二重に付く (`挿絵/x.jpg.jpg`) のを修正。
- **clippy** (`fbca3ec`): `-D warnings` が 5 件で落ちていた。すべて今サイクルの挿絵変更由来
  (`child_checked` の唯一の呼び出しが `platform::illustration_key` へ移って dead code 化、
  `illustration_key` テストの `&prefix` 3 件、`download_illustration` が
  `stored_illustrations` を得て 8 引数化)。v0.4.8 時点では 7 引数で `child_checked` にも
  呼び出し元があったため、当時の green とは矛盾しない。
- **AGENTS.md** (`7cbe79a`): 「ログ出力の境界」節を追加 (logger は lib 側だけにコンパイルする、
  コンソール行は必ず logger 経由、`safe_println` はフォールバック専用)。

## 注意 (次回以降)

- `git push` と、CLI からの HTTPS 取得 (curl ティア) はサンドボックス下で
  `schannel: AcquireCredentialsHandle failed` / `couldn't create signal pipe` になる。
  サンドボックスの外 (または full access) で実行する必要がある。
- `tests/worker_dispatch.test.mjs` は Windows の作業ツリー (`core.autocrlf=true`) で CRLF に
  なるため、そのままでは `node --test` が失敗する (v0.4.8 のメモと同じ。blob は LF なので
  Linux CI では通る)。
