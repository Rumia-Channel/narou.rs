# Conversion regression tests

`cargo test -p narou_rs --test convert_parity` runs the checked-in, synthetic
conversion regressions. They need no downloaded novels or network access.

The larger `kakuyomu_sample_matches_narou_rb_reference_byte_for_byte` test is
explicitly ignored by default because its reference novels are private,
untracked local inputs. An ignored test is not a successful parity check.
To run it, provide a library under
`sample/novel/小説データ/カクヨム/<novel>/` containing `toc.yaml`, its referenced
`本文/*.yaml` files, and a `kakuyomu_jp_*.txt` output independently generated by
narou.rb with the sample EPUB device defaults. Then run:

```sh
cargo test -p narou_rs --test convert_parity \
  kakuyomu_sample_matches_narou_rb_reference_byte_for_byte -- --ignored --exact
```

An explicit run fails if the directory or reference outputs are missing.
Do not commit downloaded novels or copyrighted reference output to supply it.

The synthetic HTML entity expectations follow narou.rb's
[`Helper::ENTITIES`](https://github.com/whiteleaf7/narou/blob/27fb741fd561e2f26aba9fdf9d9b7b4384792be4/lib/helper.rb#L137):
`&nbsp;` becomes an ordinary space, including in the full converter pipeline.

Run `node --test tests/render_links.test.mjs` for the Web UI source-link
attribute-escaping regressions. This checks the actual rendering helpers with
a minimal DOM text-serialization stub; it does not claim full-browser coverage.

Worker S3 selection/deployment regressions use only fake values and local stores:

```sh
cargo test -p narou_rs --test worker_asset_backend --test worker_storage_probe
python3 -m unittest discover -s worker_entry/tests -p 'test_*s3*.py'
cargo check -p narou_worker --target wasm32-unknown-unknown
```

These verify backend policy, mandatory deployment verification, and sanitized bounded LIST probes.
They do not run a live migration, Cloudflare deployment, or production S3 request.

Shared runtime boundary regressions:

```sh
cargo test --features lite --test novel_settings_atomic --test worker_object_updates --test http_pacing
cargo test --features lite --lib application::settings::tests
cargo test --features lite --lib native::sqlite::content::tests
```

These cover independent settings writers, canonical-save/mirror-failure acknowledgements,
full-snapshot D1 compare-and-swap (including equal-CRC collisions), physical redirect pacing,
integral-float JSON baselines and decoded converted-output storage. The D1 SQL regressions
run the production statements against SQLite; they do not replace real Workerd verification.
Run `worker_entry/tests/contract.mjs` against a real `wrangler dev` instance with
`BASE_URL`, `NAROU_ADMIN_TOKEN` and `CONTRACT_QUEUE=1` for HTTP, queue and replay contracts.

Release data-preservation regressions:

```sh
cargo test --features lite --test yaml_rollback_roundtrip
cargo test --features lite --lib platform::s3_store::tests
```

These cover failed content/metadata/marker publication followed by acknowledged writes
and reopening, interruption between provenance commit and a second publication,
bundle exports aimed at the live management directory, preserved external legacy-file edits,
and S3 copy responses that must not trigger source deletion unless a complete success result is present.

Progress and Pixiv series-tag regressions:

```sh
node --test tests/progress_bars.test.mjs
cargo test -p narou_rs --lib progress_tests
cargo test -p narou_rs --lib downloader::toc::tests
cargo test -p narou_rs --test pixiv_series_tags
```

These cover independent attempts and peers, cancellation/reconnect tombstones,
unknown TOC totals and cyclic pagination, and tag aggregation across a 31-episode
series. The update case changes only a later-page tag, keeps manual tags, and
does not download unchanged section bodies.

## Download ID reservations

```sh
cargo test --all-features --test download_new_novel_id
cargo test --all-features --lib id_allocator::tests
cargo test --all-features --lib unused_ids_are_reused_without_freeing_live_or_committed_owners
cargo test --all-features --lib concurrent_allocations_only_reuse_released_unpublished_ids
```

These cover 404 and age-consent cancellation followed by successful downloads,
reuse of unpublished IDs, stale-release fencing, imported/committed ID boundaries,
and concurrent Memory/SQLite reservations. Committed IDs are not reclaimed after removal.
They use isolated stores and synthetic HTTP, without accessing real sites.


## Persistent author tracking

```sh
python -m unittest discover -s worker_entry/tests -p 'test_author_tracking_sql.py'
cd worker_entry
node tests/run.mjs
```

The Worker runner builds the actual Wasm and assets, runs the HTTP contracts, then
`tests/author_tracking.mjs` against isolated local D1 and a controlled HTTP author source.
It covers registration across restart, discovery on empty-library updates and scheduled
events, known-work exclusion, automatic-disable/manual-check behavior, and removal during
an in-flight check without deleting novels. One-shot author downloads remain untracked.
After building the Worker, the author smoke can also run independently with
`node tests/author_tracking.mjs`. Worker author management is exercised through
the Web UI's HTTP APIs, without a native remote CLI. The local state is removed
in `finally`; no production D1 or S3 is used.

On Unix, each smoke-test Wrangler runs in its own process group; teardown stops
the entire npx/Wrangler/workerd group. Windows uses `taskkill /T /F`.
Successful checks must also exit and release their local fixture state.
